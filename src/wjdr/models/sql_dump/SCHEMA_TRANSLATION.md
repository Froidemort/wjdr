# SQL Dump Translation Notes

This package mirrors `resources/sql/WJDR_2026-04-07T15_51_45.999Z.sql` as closely as possible, but several raw SQL definitions could not be represented literally in valid SQLModel or SQLAlchemy metadata.

## Intentional translations

- Bridge tables that declared foreign-key columns as `GENERATED BY DEFAULT AS IDENTITY` were modeled as plain composite primary-key foreign keys instead.
- Character-owned foreign keys were modeled on `CharacterTable` rather than by reproducing the reversed `ALTER TABLE <child>.id REFERENCES CharacterTable(...)` pattern from the dump.
- `CharacterCareerLinkTable.career_id` was translated from `INTEGER` to `UUID` so it can reference `CareerTable.id` consistently.
- `ObjectTable.equipment_id` is treated as the owning foreign key to `EquipmentLink.id` instead of reproducing the inverted `EquipmentLink.id REFERENCES ObjectTable(equipment_id)` form.
- `WeaponTable.attribute_id` is treated as the owning foreign key to `WeaponAttributesTable.id` instead of reproducing the inverted `WeaponAttributesTable.id REFERENCES WeaponTable(attribute_id)` form.
- `TalentChoiceSkillLinkTable.talent_id` was modeled as a normal composite-key foreign key, not an identity column.
- `CareerSkillChoiceSkillFreeChoiceSkillLinkTable` preserves the dump's `career_skill_not_all_null` check constraint exactly.
- `CareerTalentChoiceTalentFreeChoiceTalentLinkTable` preserves the dump's nullable polymorphic columns, but the inverted foreign keys onto `ChoiceTalentTable.id`, `FreeChoiceTalentTable.id`, and `CareerTalentChoiceTalentFreeChoiceTalentLinkTable.id` were not reproduced literally.
- `ChapterTable.medias` remains as the unique nullable integer from the dump even though `ChapterMediaLinkTable` also exists.
- PostgreSQL enums are stored using the exact SQL dump values, including accented values such as `féminin` and `médiocre`.

## Verification

- `tests/test_sql_dump_models.py` verifies every translated table name from the source dump is present in SQLModel metadata.
- The same test module verifies indexes, foreign keys, enum values, defaults, composite primary keys, and the preserved check constraints.
